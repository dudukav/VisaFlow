# OCR spike для VisaFlow

Сравнение `pypdf` и локального Tesseract для синтетических документов из [#14](https://github.com/dudukav/VisaFlow/issues/14). Набор содержит 20 одностраничных PDF формата A5: четыре набора значений, включая эталон #2, в пяти вариантах. В [манифесте](cases/manifest.json) указаны `surname`, `givenName`, `documentNumber` и `expiresOn` для каждого файла.

| Вариант | Входной PDF |
|---|---|
| `text_layer` | Текстовый слой ReportLab |
| `scan_300dpi` | Растровая страница, исходное разрешение 300 DPI |
| `scan_150dpi` | Растровая страница, исходное разрешение 150 DPI |
| `scan_rotated` | Растровая страница 300 DPI с поворотом на 3° |
| `scan_low_contrast` | Растровая страница 300 DPI с коэффициентом контраста 0,60 |

## Как повторить прогон

Нужны Python 3.12, `pdftoppm` из Poppler и Tesseract с языковой моделью `eng`. На macOS Poppler и Tesseract можно установить командой `brew install poppler tesseract`. Проверь модель через `tesseract --list-langs`.

Запусти из корня VisaFlow. Прогон создаст отдельный набор и новый отчёт во временном каталоге, чтобы измеренный [report.json](report.json) можно было использовать для сравнения.

```bash
spike_dir=backend/processor/ocr_spike
ocr14_work="$(mktemp -d /tmp/visaflow-ocr14.XXXXXX)"
python3 -m venv "$ocr14_work/venv"
ocr14_python="$ocr14_work/venv/bin/python"
"$ocr14_python" -m pip install -r "$spike_dir/requirements.txt"

"$ocr14_python" "$spike_dir/generate_fixtures.py" \
  --baseline api/fixtures/mvp1/passport \
  --output "$ocr14_work/cases"

"$ocr14_python" "$spike_dir/benchmark.py" \
  --manifest "$ocr14_work/cases/manifest.json" \
  --runs 3 \
  --output "$ocr14_work/report.json"

printf '%s\n' "$ocr14_work/report.json"
```

Для прогона на уже сохранённых PDF пропусти генерацию и передай `--manifest "$spike_dir/cases/manifest.json"`.

## Как считались показатели

- `pypdf` извлекает текст первой страницы. Tesseract сначала получает изображение первой страницы через `pdftoppm` с 300 DPI, затем распознаёт его с `-l eng --oem 1 --psm 6`. Повторный рендер скана 150 DPI сохраняет ограничения исходного разрешения.
- Оба метода используют общий разбор полей. Для точного совпадения нормализуются пробелы, регистр и похожие символы в значениях сохраняются. Дата должна быть действительной календарной датой в формате `YYYY-MM-DD`.
- Точность считается по первому завершённому прогону каждого PDF. Время измеряется по всем трём повторам без прогрева. Время Tesseract включает рендер страницы, запуск процесса и временный ввод-вывод.
- Confidence поля Tesseract равен минимальной оценке среди слов значения, приведённой к шкале от 0 до 1. Для `pypdf` в отчёте стоит `null`. Ошибки с confidence ≥ 0,85 считаются отдельно.

## Результаты

Прогон от 19 ноября 2026 года выполнен на macOS 26.6.2, arm64, с Python 3.12.14, pypdf 6.21.4, Tesseract 5.5.4 и Poppler 26.11.0. Все 120 запусков завершились без ошибок и таймаутов. Значения полей и статусы совпали между повторами.

| Метод и выборка | Фамилия | Имя | Номер документа | Дата окончания | Все поля | p50 / p95, мс |
|---|---:|---:|---:|---:|---:|---:|
| pypdf, 4 PDF с текстовым слоем | 4/4 | 4/4 | 4/4 | 4/4 | 4/4 | 1,107 / 2,456 |
| pypdf, 16 сканов | 0/16 | 0/16 | 0/16 | 0/16 | 0/16 | 0,728 / 2,496 |
| Tesseract, все 20 PDF | 20/20 | 15/20 | 10/20 | 20/20 | 10/20 | 542,360 / 652,777 |
| Tesseract, 16 сканов | 16/16 | 12/16 | 8/16 | 16/16 | 8/16 | 552,544 / 678,586 |

На 16 сканах `pypdf` вернул `no_text_layer`. Tesseract извлёк все поля, но ошибся в восьми номерах и четырёх именах. В номерах были подмены `I/1` и `O/0`. Все четыре ошибки имени — `AI` → `Al` — произошли с confidence ≥ 0,85. Для номера и даты таких уверенных ошибок в этом наборе не было. Самый высокий p95 среди вариантов у повёрнутого скана — около 722 мс.

Результат ограничен одним макетом, одной страницей, латиницей и четырьмя наборами значений. Варианты одного набора повторяют те же значения, поэтому один сбой распознавания может проявиться в нескольких PDF. Время зависит от машины.

## Решение для #15 и ручной ввод

**Ограниченный GO.** Использовать `pypdf` для документов с пригодным текстовым слоем, Tesseract — для подготовки черновика. Предложенный для спайка ориентир — минимум 15/16 точных совпадений по каждому критичному полю на сканах. Дата прошла его с 16/16, номер получил 8/16. [#15](https://github.com/dudukav/VisaFlow/issues/15)

1. Сначала читать текстовый слой. Если найдены все четыре поля и дата валидна, отдать значения на подтверждение. При пустом или неполном слое либо невалидной дате запустить OCR.
2. На пути через OCR **номер документа всегда вводится вручную**. Для остальных полей можно предложить распознанное значение, если формат валиден и confidence ≥ 0,85. Пропуск, невалидный формат или confidence ниже 0,85 требуют ручного ввода или исправления поля.
3. Если OCR завершился ошибкой, истёк по таймауту или не вернул пригодных значений, открыть форму с пустыми полями для ручного ввода.
4. Worker в #15 возвращает распознанные значения и признаки полей, требующих внимания, по согласованному callback-контракту. В [#16](https://github.com/dudukav/VisaFlow/issues/16) пользователь сверяет и явно подтверждает все четыре поля, включая поля с высоким confidence. После подтверждения Go запускает проверки.
