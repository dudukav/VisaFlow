# Матрица трассируемости требований (RTM) — VisaFlow MVP

| Поле | Значение |
|---|---|
| Продукт | VisaFlow, Telegram Mini App |
| Релиз | Туристические визы Италии, Испании и Японии |
| Источники | PRD 0.2, SRS 0.2, User Stories 0.2 |
| Статус | Draft; тесты и метрики имеют статус Planned |
| Версия / дата | 0.2 · 22.09.2026 |

> **Что такое полная трассируемость.** Каждое требование связано назад с пользовательской историей/бизнес-целью и вперёд с критерием приёмки и проверкой. Требование без источника — кандидат на удаление; требование без проверки — дырка покрытия.

## Легенда идентификаторов

- **BG** — бизнес-цель PRD;
- **US** — пользовательская история;
- **AC** — критерий приёмки истории;
- **FR / NFR** — функциональное / нефункциональное требование SRS;
- **BR** — бизнес-правило SRS;
- **TC** — тест-кейс;
- **M** — продуктовая метрика/мониторинг после релиза.

## Проверка полноты (нет сирот)

- Все 38 FR и 12 NFR Матрицы A имеют источник и способ проверки.
- Каждый TC Матрицы B связан хотя бы с одним FR/NFR/BR.
- Каждая BG Матрицы C обеспечена требованиями и закрыта тестами и/или метрикой.
- BR-001/BR-002 проверяются в TC-2.1/TC-3.2; BR-003/BR-004 — в TC-4.6; BR-005 — в TC-6.4; BR-006/BR-007 — environment scan в M-6.
- Перед реализацией статус строки меняется `Planned → Implemented`; после прогона — `Passed`, `Failed` или `Blocked`.
